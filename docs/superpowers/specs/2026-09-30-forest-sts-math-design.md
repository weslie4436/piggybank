# 森林尋寶：殺尖塔棋盤 × 小二數學

日期：2026-09-30  
狀態：已與使用者對過口頭規格，待實作前再看一次本檔。

## 目標

把現有「五間房、點選項按鈕」的森林探險，換成 CardGame 已調好的殺尖塔戰鬥盤操作。孩子把答案卡拖到對應的怪物身上；算對就解決那隻怪，金幣進待領，回銀行用現有領取對話框與紅點自己點領。美術第一版只用佔位框。

對象是小二。操作像殺尖塔，規則不是殺尖塔的能量／結束回合／敵人意圖。

## 畫面

進森林＝全螢幕戰鬥（沿用現有 `.adventure-screen` 殼：返回、今日已賺／待領、音效）。

規則與資料只有一套；**直立與橫屏是兩套棋盤幾何**，不能拿橫向殺尖塔盤縮成直的。旋轉中途只重排位置，不重開遭遇、不洗牌、不扣血。

切換依據是螢幕方向（`orientation`＋`visualViewport` 變化），**不要**用「寬度小於 700px」冒充直立——窄桌機視窗仍可能是橫的。

### 橫屏（iPad 橫拿、桌機寬窗、手機橫拿）

對齊 CardGame `BattleScene`：戰場佔滿頂列以下；怪列在上半水平置中；手牌扇形貼底。

```
[返回]                         血／待領
              怪    怪    怪
         （1～3 隻，水平 gap，題目＋血條在各怪上）

        [12]  [17]  [11]  [18]  [16]
              扇形：中央高、兩側低微傾
```

橫拿 iPhone 也走這套，但怪與牌縮小、左右避開安全區（瀏海／Home 條），手牌可點面積仍要夠孩子手指。

### 直立（iPhone 直拿、iPad 直拿）

上戰場、下手牌，中間不夾地圖。三隻怪仍同時在場，但改為較窄的置中列：佔位框變瘦高、互相可少量重疊，題目字不能被擋住。手牌貼底、扇形更緊（重疊較多、單張較高），底部加 `safe-area-inset-bottom`，拖牌時牌要能畫在怪的命中框上面（拖曳層 z-index 高於怪）。

```
[返回]        血／待領

      怪  怪  怪     ← 瘦高佔位，題目在框上或框內上半
      （三隻仍一列，不要改成直向清單點選）

   [12][17][11][18][16]
        貼底緊扇形
```

直立時禁止：把三隻怪改成一次只顯示一隻、或改回按鈕答題。操作仍是拖到怪身上。

### 共同

- 怪身上的字是題目（例如 `3+9`），不是怪名當主資訊。
- 手牌是整數答案。
- 拖到正確的怪＝命中；拖到錯誤的怪或空白＝未命中。
- iPhone／iPad／桌機同一套 pointer 拖曳；點選不當作出牌。
- 孩子血條在頂列附近，兩種方向都要看得見，不可被手牌蓋住。

返回是共用「返回」。領錢不新做問句卡，走銀行既有撲滿對話框（`#claim-bubble`）與可領時的紅點／限動環（`claim-go.is-ready`）。

## 戰鬥規則

- 孩子 5 滴血。血量每次進入森林回滿；不跨日扣除。
- 一般怪 1 滴血：丟中正確數字就解決。
- 精英怪 2 滴血＋較難題：同一隻佔位框。第一次丟中後血變 1，題目換成第二題（仍較難）。要兩張對應的正解卡，不是同一數字打兩次（除非兩題答案碰巧相同）。
- 丟對：該牌離開手牌，怪扣血／倒下，受擊表現。倒地的怪不再接牌。
- 丟錯（錯怪或錯數字）：牌彈回扇形，孩子扣 1 滴血，孩子受擊表現。牌不消失。
- 血歸零：Game Over，回銀行。不扣已經在撲滿裡的錢，也不收回待領。
- 怪不會出手。失敗只來自丟錯。

## 一天的遭遇

沒有地圖。怪一波一波來：目前這波全倒，下一波才出現。

用當天 `day_key`（既有下午 4 點切日）加孩子 id 做種子，一天只生成一次：

- 波數：3 或 5，各半。
- 每波 1～3 隻。有的日子怪多、有的日子少。
- 精英：整日最多 1 隻；約五分之一的日子出現，不保證每天都有。出現時放在中後段波次，不放第一波。
- 題目：台灣小二程度，加減為主，可有進位／退位；乘僅限小範圍（現況已有 2～5 × 2～10，可留作少數）。同一波答案不可重複，以免一張牌能同時解兩隻。
- 手牌：這一波所有還需要的正解（精英未受傷＝兩題都發）＋ 2～3 張接近的誘答（例如 ±1～3、進位漏算）。一波一副手；換波重發，不把上一波剩牌帶走。

## 金幣

- 當日掉落總和先抽一個整數 S（18～30），再把 S 拆給當日每隻怪。波數多則單隻較薄，波數少則單隻較厚。
- 有精英時：精英拿 S 裡最大的一份，且至少比任一普通怪多 2 元；其餘均分給普通怪（餘數給較後的怪）。沒有精英時普通怪均分 S。
- 打死才產生「待領」，不自動入帳。
- 待領走既有領取佇列（與零用錢／獎金同一條 `claimQueue`），文案改成孩子能懂的森林掉落，例如「森林裡撿到 10 元」。紅點／對話框在銀行主畫面，不在戰鬥裡跳出第二套確認。
- Game Over 或中途返回：已打死的怪維持解決、已產生的待領保留、未打的怪下次進來繼續。不會重複發同一隻的錢。
- 帳本仍只追加；入帳只發生在孩子點領之後的 SQLite 交易。前端動畫不得自行加餘額。

## 保險庫與資料

現有 `adventure_pois`（五房）＋每房一題的 `adventure_questions` 不夠表達波次／精英雙題／待領。實作時改成以「當日遭遇」為單位，例如：

- 當日遭遇：波數、當日掉落上限已分配額。
- 怪物列：波次、是否精英、血上限、題目序列（精英兩題）、答案序列、掉落金額、已解決、待領是否已進佇列。
- 領取：併入既有 pending grant／claim，不要另做會跳過帳本的捷徑。

舊的五房進度不必遷移：新遭遇以新 `day_key` 或新 schema 版本生成；當天若已用舊表打過，以「新結構覆蓋當日探險、不改寫已入帳的 grant」為準，實作時用測試鎖死。

日期一律保險庫 Asia/Taipei，與零用錢同一 `_adventure_day_key`（下午 4 點切日）。

API 概念（名稱實作時可調，語意不可歪）：

- 讀遭遇：波次、場上怪、手牌、孩子血、待領摘要。手牌與正確答案對照只留保險庫；回應可含手牌數字與怪的題目，不得讓前端自己判對錯。
- 出牌：`monster_id` + 手牌上的數字。保險庫判定對錯、扣血、倒怪、產生待領、是否進下一波／當日結束／Game Over。
- 領取：沿用 `/api/claim`（或同等已存在的 pending grant 領口），不另開會重複入帳的探險專用入帳。

同週期／同隻怪只能領一次掉落。餘額不得為負。

## 產品邊界

- 仍是撲滿的探險模式，不是獨立遊戲站。入口維持 GitHub Pages → 隧道 → 保險庫。
- 戰鬥是產品專有物件（與撲滿舞台同級），殼（返回、領取對話框、紅點）不新造輪子。
- 第一版只有一個孩子帳戶，與現況相同。

## 驗收

- 三端都能把牌拖到指定怪上；鬆手才結算。
- 直立、橫屏各驗一輪（至少 iPhone 直／iPad 橫，並在戰鬥中旋轉一次）：怪與手牌不互蓋到不能拖、題目仍可讀、進度不重置。
- 畫面上 3 隻怪、手牌同時有正解與誘答時，只有對應答案能解決該怪。
- 丟錯扣 1 血、牌回來；5 次丟錯回銀行，撲滿既有金額不變。
- 再進森林：已倒的怪不再出現，剩餘波次接續，血回 5。
- 精英要兩題兩張牌；第一題過後題目更換。
- 當日掉落合計在 18～30；精英日較肥但仍不超過 30。
- 打死後錢在銀行對話框＋紅點，點了才進撲滿與帳本。
- 佔位框可玩；不依賴正式怪圖／牌面圖。
